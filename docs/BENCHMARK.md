# CodingVault-Bench — 公开可复现评测基准与消融实验

> 一键复现: `python benchmarks/run_bench.py` (30 秒级, 零网络零第三方依赖)。
> 本文档全部数字由脚本真实跑出并落盘 JSON (`benchmarks/results/`), 无任何手工润色。

## 1. 评测集构成

**语料** (`benchmarks/coding_vault_bench/corpus/`, 由 `build_corpus.py` 固定 seed 生成):

| 项 | 值 |
|---|---|
| 演进会话链 | 18 条 × 3 个虚构项目 (phoenix-api 支付网关 / quartz-ui 组件库 / cobalt-sync 数据同步) |
| 快照 | 99 个 (每链 5-7 个累积演进版本, 带完整 parent_snapshot lineage) |
| 对话与工具块 | 4,234 块 (~1.7MB JSON) |
| 内容形态 | 用户拍板 / assistant 裁决与踩坑 / thinking / tool_call+result / 大段日志噪音 |
| 脱敏 | 零真实密钥、零本机路径 (全部 `D:\work\<虚构项目>`), 生成器内置泄漏自检 |

**金标** (`queries/`, 162 条, 全部由链定义参数人工推导 — Zero Data Leakage):

| 维度 | 条数 | 考核点 |
|---|---|---|
| `single_session` | 54 | 单会话精确命令/参数/错误码召回 (含 18 条跨写法: 语料 camelCase ↔ 查询 snake_case) |
| `multi_session` | 18 | 跨会话关联定位 |
| `temporal_update` | 42 | 方案推翻后的当前事实召回 + 过期记忆误召回 |
| `handoff` | 24 | 4K/2K token 预算交接简报的文件/踩坑保留率 |
| `abstention` | 24 | 从未决定过的干扰问题识别 (拒答) |

## 2. 消融实验结果

复现命令: `python benchmarks/run_bench.py`。下表为 2026-11-18 实测 (Windows 10 x64, Python 3.9, 纯标准库;
与 `benchmarks/results/bench_results.json` 逐字一致)。

### Panel A — 检索演进 (同一语料/查询, 162 题中的检索维度)

| 变体 | Recall@1 | Recall@5 | MRR@10 | 版本入侵率↓ | 拒答准确率 | 索引 MB | P50 ms | P95 ms |
|---|---|---|---|---|---|---|---|---|
| Baseline0 (v0 词集交集) | 0.8070 | 0.9912 | 0.8813 | 0.5714 | 0.4583 | — | 121.2 | 140.5 |
| V1 Vanilla BM25 | 0.6930 | 0.9474 | 0.7751 | 0.8571 | 0.6667 | 0.20 | 0.3 | 0.6 |
| V2 = V1 + 代码感知分词 | 0.8947 | 0.9825 | 0.9251 | 0.9524 | 0.9167 | 0.21 | 0.6 | 0.9 |
| V3 = V2 + 角色加权 + Lineage 折叠 | 0.8947 | 0.9825 | 0.9269 | **0.0000** | 0.9167 | 0.21 | 0.8 | 1.1 |
| **Ours (Full Core v2)** = V3 + 时间衰减 | 0.8070 | 0.9825 | 0.8687 | **0.0000** | 0.8333 | 0.21 | 0.9 | 1.4 |

要点:
- **代码分词区分度 (V1 vs V2)**: 18 条跨写法查询 (语料写 camelCase, 查询写 snake_case) 上
  vanilla 分词命中不了 — V2 的 Recall@1 (+0.20) 与拒答准确率 (+0.25) 差距即代码分词的净贡献。
- **版本入侵率**: 无折叠变体 (V1/V2) 的 Top-5 大量被同链历史版本占据 (0.86–0.95); Lineage
  折叠归零 — 同一演进链只出一个最新版命中。
- **Baseline0 的 0.99 Recall@5 是刷分假象**: 词集交集靠海量弱命中堆高召回, 但拒答 0.46
  (对"未决定过"的问题瞎答) + 版本入侵 0.57 + 每查询 ~120ms 全量扫描 — 综合质量全面劣于 v2。
- **Ours (时间衰减)** 在时间均匀分布的合成语料上 R@1 略低于 V3 (0.807 vs 0.895): 衰减的
  价值在真实时间偏斜库 (旧方案快照该退场), 均匀语料无此收益 — 诚实记录, 不修饰。

### Panel B — 记忆演进 (temporal_update 42 题)

| 引擎 | Temporal Active Recall | Stale Memory Intrusion↓ | 记忆总量 | 活跃记忆 | v0.1 误杀率 |
|---|---|---|---|---|---|
| v0 宽松规则 | 0.4762 | 0.9762 | 396 | 396 | — |
| v0.1 硬噪音闸门 | 0.5000 | 0.9762 | 90 | 90 | **1.0000** |
| **v2 双时态引擎** | **0.8810** | **0.0000** | 144 | 107 | — |

要点:
- v0: 重复摘录刷屏 (396 条) + 方案推翻后新旧同时返回 (入侵 0.98)。
- v0.1: 降噪 4× 但**把含行内代码实体的技术裁决全部误杀** (误杀率 1.0 — 正是真实库中
  `决定采用 \`FTS5\` 索引` / `- **结论**：…` 类决策被吃掉的缺陷)。
- v2: 双时态覆盖后默认只回当前有效记忆 (入侵 0.0), 召回接近翻倍; `include_history=True`
  可完整追溯 A→B→C 演变链 (superseded_by 指针齐全, 见 tests/test_cv_memory_v2.py)。

### Panel C — 交接压缩 (handoff 24 题, 4K/2K token 预算)

| 变体 | 文件保留达标率 (≥95%) | 踩坑保留率 | 压缩比 |
|---|---|---|---|
| naive 顺序截断 | 0.9167 | 1.0000 | 0.8157 |
| **compress_brief 五槽位装配** | **1.0000** | **1.0000** | **0.4238** |

要点: 朴素截断在多文件链上丢触碰文件 (只看到链头部); 五槽位装配把「触碰文件拓扑 /
已证伪死路」提为显式槽位, 同预算下信息覆盖完整, 压缩比还低一半。

## 3. 本机千级快照规模实测

复现命令: `python benchmarks/bench_scale_local.py --vault <你的vault>` (只读硬链接/拷贝副本, 绝不改写原库;
本机落盘样例 `benchmarks/results/scale_local.json`)。

实测环境: 本机生产 vault (2,006 快照 / 1.8GB 原始 JSON / 最长演进链 164 版);
下表数字与 `benchmarks/results/scale_local.json` 逐字一致。

| 指标 | v0 (升级前) | v2 (本版) | 变化 |
|---|---|---|---|
| 索引体积 | 778.5 MiB (`index_cache.pkl`) | **100.9 MiB** (`search_index.db`, zlib 压缩倒排) | **-87.0%** |
| 常驻内存 (索引态) | ≈索引体积整载 (0.8GB 级) | 块元数据紧凑数组 ≈25 MB | 构建期外零大对象 |
| 全量构建 | 慢 (pickle 整体反序列化) | 208.7 s 一次性 (之后纯增量, 毫秒级) | — |
| 冷启动查询 | 每次全量文件扫描 (秒级) | 375.5 ms (装载索引) + 后续热查 | — |
| 查询 P50 / P95 | 文件扫描秒级 | **23.1 ms / 39.0 ms** (15 条工程查询, 见 scale_local.json) | P95 < 50ms 达标 |
| 索引文档数 | 1,497,299 块 (含演进重复) | 353,978 唯一块 (链内首见去重) | 4.2× 去重 |

> v0 的 778.5 MiB pickle 是本方案要消灭的对象: 词集交集评分无 IDF / 无长度归一 /
> 无角色权重, 且 2000 快照的演进重复全部入索引。v2 用「链内首见去重 + 停用词项丢弃
> (df>45%) + 叙述块词量上限 + tf 均一词项免数组 + tool 块锚点化索引 + zlib 倒排压缩」
> 六项把体积压到 1/8.1, 同时把检索质量反向提升 (见 Panel A — v0 的词集交集在拒答与
> 版本入侵上全面劣于 v2)。

## 4. 反作弊与可复现声明

- 查询集由 `build_corpus.py` 的**链定义参数**推导 (哪个版本改了哪个文件 / 哪次裁决推翻了哪条),
  不从生成文本反向抽取; 分词器与提取器代码不含任何评测词。
- 各变体跑完全相同的语料与查询; 每变体构建前清空上一配置的落盘索引, 且 VaultIndex
  hdr 携带检索配置指纹 (权重/分词模式/衰减), 配置不符一律判失效重建 — 索引串档在
  结构上不可能。全部指标由 `run_bench.py` / `bench_scale_local.py` 真实计算并落盘
  `benchmarks/results/*.json`, Markdown 表由 JSON 渲染, 无手改。
- 已知局限 (诚实记录): v2 的 supersede 采用保守显式推翻语义 (仅"改为/废弃/不再使用"
  等明确信号触发), 无锚点的陈述不参与跨句覆盖 — 宁可漏覆盖, 不可误覆盖。
- `+Dense` 变体 (OpenAI 兼容 embedding RRF) 仅在 `CV_EMBEDDINGS_URL` 配置时运行;
  缺省跳过, 零外发。
